== 진입 (bootstrap)

미니앱 진입 직후 **1회 호출**해 "나는 누구인가 + 쓸 수 있는가"를 한 번에 받는다.
**부트스트랩이 곧 로그인이다** — 응답에 access·refresh 토큰이 동봉된다(v4).
요구 정본은 `backend/docs/domain/auth.md` §5-2 (v4) · 이용권 스키마는 `payment.md` §5-3.

=== `POST /api/v1/bootstrap`

**공개 경로**(게이트 밖 — 토큰 발급 지점이라 토큰을 요구할 수 없다). 단 **`X-Anonymous-Key` 헤더는 필수**다 —
없으면 등록할 대상이 없어 401 `AUTH_001`, 형식 위반이면 401 `AUTH_002`.
멱등하다 — 몇 번 호출해도 사용자는 하나이고 응답도 같다.

operation::bootstrap-entry[snippets='http-request,request-headers,http-response,response-fields']

* `newUser` 로 온보딩 노출을 분기한다.
* **`auth.accessToken`/`auth.refreshToken` 을 로컬에 보관**한다 — 이후 전 API 는
  `Authorization: Bearer {accessToken}`, 만료 시 갱신은 인증 절 참조.
* 재호출 = 재로그인 — 토큰이 새로 발급된다(기존 refresh 는 폐기되지 않는다 — 다기기 정상 케이스).
* `entitlement` 는 이용권 상태 절(payment)과 **같은 모양**이다 — S1 배지를 즉시 렌더링하고,
  **분기는 `accessible` 하나로만** 한다.

=== 실패 처리

operation::bootstrap-entry-fail-missing-key[snippets='http-response']
operation::bootstrap-entry-fail-malformed-key[snippets='http-response']

|===
| 응답 | 프론트 행동

| 401 `AUTH_001` (헤더 누락) | SDK `getAnonymousKey()` 재호출 1회 → 실패 시 오류 안내 후 종료
| 401 `AUTH_002` (형식 위반) | 재시도해도 같다. "이용할 수 없는 환경" 안내 후 종료
| 500 `COMMON_002` | 백오프 재시도
|===

[CAUTION]
====
**부트스트랩 실패(500)를 "이용권 없음"으로 간주하지 않는다** — 부분 실패를 허용하지 않는
설계라(전체 500), 실패를 미보유로 오해하면 **이미 결제한 사용자에게 결제 유도 화면**을 띄우게 된다.
====
