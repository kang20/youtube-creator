== 인증 (auth)

익명키 로그인은 부트스트랩(진입 절)이 담당한다 — **부트스트랩이 곧 로그인이고 토큰 발급 지점**이다.
이 장은 토큰 **갱신** 계약만 다룬다. 요구 정본은 `backend/docs/domain/auth.md` v4.

=== 토큰 갱신 — `POST /api/v1/auth/refresh`

인증 게이트 **밖**이다 — 자격 증명이 만료된 상태에서 부르는 API 이기 때문이다.
본문의 refresh 토큰이 자격 증명이다.

operation::auth-refresh[snippets='http-request,request-fields,http-response,response-fields']

[IMPORTANT]
====
**회전식이다.** 응답을 받는 순간 요청에 쓴 refresh 는 폐기된다 — 반드시 **새 쌍으로 교체 보관**한다.
같은 refresh 를 다시 보내면 서버가 탈취 신호로 간주해 **그 사용자의 refresh 전부를 폐기**한다
(`AUTH_005` → 부트스트랩 재로그인. 익명키는 SDK 가 늘 주므로 마찰 없음).
====

operation::auth-refresh-fail-invalid[snippets='http-response']

|===
| 응답 | 프론트 행동

| 200 | 새 쌍 보관 → 원 요청 1회 재시도
| 401 `AUTH_005` (만료·미존재·재사용) | 부트스트랩 재실행(재로그인) → 원 요청 1회 재시도
|===

* 갱신·재로그인·재시도는 **각 1회씩만** — 무한 루프 금지. `AUTH_004 → refresh → 재시도` 는
  HTTP 인터셉터 한 곳에 두고 화면 코드는 모르게 한다.
