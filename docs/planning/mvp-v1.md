# 1. MVP 설계안

## 1-1. 한 줄

토스 안에서, 앱 설치·가입 없이, **폰만으로 기존 영상에 자막을 입혀 받는다.**
1차 출시 솔루션은 **자막 생성 1종**이며 **월 정기구독**으로 판다.

## 1-2. 사용자 여정

```
① 진입            토스 → 미니앱. anonKey 발급 (로그인 없음)
② 솔루션 목록     제공 솔루션 카드 목록 (현재 1종: 자막 생성)
③ 솔루션 상세     Before/After 예시 영상 · 지원 범위 · 처리 시간 · 가격
④ 구독 결제       IAP 자동갱신 구독(MONTHLY) → 서버가 anonKey↔orderId 매핑 저장 (로그인 없음)
⑤ 영상 선택       Device.getAlbumItems(types:["VIDEO"]) → 제약 검사 → 초과 시 즉시 반려
⑥ 업로드·분석     서버 업로드 → STT → 작업 상태 폴링 (비동기 필수)
⑦ 대본 검토       타임스탬프별 자막 대본 표시 → 사용자 수정 → 확정
⑧ 번인·수령       서버 ffmpeg 자막 번인 → 결과 영상 저장/공유
```

## 1-3. 화면 목록

| # | 화면 | 핵심 |
|---|---|---|
| S1 | 솔루션 목록 | 카드 1장(자막 생성). 구독 상태 배지 |
| S2 | 솔루션 상세 | **Before/After 예시 영상 필수** — 체험이 없으므로 여기가 설득의 전부 |
| S3 | 구독 결제 | IAP 구독 바로 진입. **로그인 화면 없음** |
| S4 | 영상 선택 | 앨범 피커 + 제약 안내(길이 기준으로 노출) |
| S5 | 처리 중 | 진행률·예상 시간. 이탈 후 복귀 가능 |
| S6 | 대본 편집 | 타임스탬프별 행 편집. 재생 위치 동기화 |
| S7 | 결과 | 미리보기 → 저장/공유 |
| S8 | 작업 목록 | 최근 작업 + 상태(처리중·완료·만료). **처리 중이면 S1 에 배너로 노출** |

## 1-4. 기능 범위

**포함** — 익명 진입 · 솔루션 목록/상세 · 월 구독 결제(+미결 주문 복원) · 영상 선택 ·
STT 자막 생성 · 타임스탬프 대본 편집 · 자막 번인 · 결과 영상 수령 · **작업 목록(이탈 복구용)**

**제외 (백로그)**

| 뺀 것 | 이유 |
|---|---|
| 자막 스타일 커스터마이징(폰트·색·위치) | 프리셋 1종으로 시작. 선택지는 이탈 지점이다 |
| 번역·다국어 자막 | 1차 가치와 무관 |
| 보관함의 폴더·검색·이름변경 | 작업이 수십 개 쌓인 뒤의 문제. 목록만 둔다(쟁점 6) |
| 유튜브 계정 연동 / 쇼츠 AI 제작 / 방향성 진단 | 로드맵 |

## 1-5. 인증·결제 모델

**토스 로그인은 쓰지 않는다.** 전 구간 익명키 단일 식별.

| 구간 | 수단 |
|---|---|
| 전 구간 식별 | `User.getAnonymousKey()` → `X-Anonymous-Key` 헤더. **로그인 없음** |
| 익명키 검증 | 서버에서 anon-key verify API 로 검증 (mTLS 필요 여부 🔶) |
| 구독 | 앱인토스 IAP **자동갱신 구독(MONTHLY)** · `createSubscriptionPurchaseOrder` |
| 구독 소유권 | 서버가 **`anonKey ↔ orderId` 매핑**을 보관 — 이것이 구독 소유의 정본 |
| 구독 상태 | 서버가 `orderId` 로 구독 조회 + `subscription.status_changed` 웹훅 |
| 미결 주문 | 앱 기동 시 `getPendingOrders` → `completeProductGrant` 복원 **필수** |

> **anonKey 는 기기가 아니라 사용자(계정) 기준이다.**
> 토스 공식: *"미니앱마다 고유한 값이고, **같은 사용자는 같은 미니앱에서 항상 같은 값을 받아요**"*
> ([토스 블로그](https://toss.im/apps-in-toss/blog/toss-login-vs-anonkey)).
> 같은 문서가 토스 로그인이 필요한 경우로 드는 것은 *"본인 확인이나 중복가입 방지처럼,
> 앱인토스 밖 계정과 같은 사람인지 연결해야 할 때"* 뿐 — **기기 변경 복원은 로그인 필요 사유가 아니다.**
> 따라서 검수 항목 "기기 변경 시 결제 데이터 유지"는 anonKey 만으로 충족될 것으로 본다.
>
> 🔶 **단, 문서에 명시된 문장은 없다.** "기기 변경·재설치"를 직접 다룬 공식 문구가 없고,
> 커뮤니티 [4279](https://techchat-apps-in-toss.toss.im/t/user-identifier/4279) 에서 같은 질문에 확답이 나오지 않았다.
> 결제 소유권이 여기 걸려 있으므로 **실환경에서 한 번은 확인한다** → 스파이크 6번.
> (샌드박스는 mock 을 반환하므로 샌드박스 검증은 무의미하다.)
>
> ⚠️ **미니앱이 바뀌면 anonKey 도 바뀐다.** 앱을 새로 출시하면 승계되지 않는다 — DB 설계 시 주의.

## 1-6. 입력 영상 제약 — 🔶 전부 미확정

> **이 절의 수치는 하나도 확정되지 않았다.** 스파이크 1~3 결과가 나와야 정한다.
> 아래는 논의 출발점일 뿐이므로 `/usecase` 로 넘길 때 그대로 옮기지 않는다.

**잡힌 방향** (쟁점 2)
- 길이가 아닌 **용량·해상도 기준**으로 제한한다
- **가로·세로 모두** 허용한다
- **안내는 길이로, 방어는 용량으로** — 용량은 사용자가 예측할 수 없으므로 화면에는 길이만 노출

**미확정 값 🔶**

| 기준 | 논의값 (미확정) | 역할 | 확정 조건 |
|---|---|---|---|
| 파일 용량 | 50MB? | 하드 방어. base64 팽창 1.33배 → 힙 ≈67MB | 스파이크 1 (웹뷰 메모리 실측) |
| 해상도 | 1080p 이하? | 초과 시 업로드 전 다운스케일 | 스파이크 1 |
| 길이 | 3분 이하? | 화면 안내용 + 인코딩 원가 상한 | 스파이크 2·3 (업로드·번인 시간) |
| 다운스케일 위치 | 클라 / 서버? | 미정 | 스파이크 1 |

**확정된 것 하나** — 토스앱 **5.261.0 이상** (`getAlbumItems` 하한). 미만은 안내 후 종료.

초과 시 **선택 직후 즉시** 사유를 밝히고 반려한다(업로드 시작 후 실패는 최악의 UX).

## 1-7. 비기능 요건 (검수 직결)

- 인터랙션 반응 **2초 이내** → ⑥·⑧은 **반드시 비동기 + 상태 폴링**
- 비정상 메모리 증가 금지 → dataUri 처리 구간이 최대 위험점

- **보관 정책(쟁점 6)** 🔶 **미확정** — 방향: 영상 파일은 일정 기간 후 자동 삭제 /

  **기간·범위는 스토리지 원가 산정 후 결정**

# 2. 선행 작업 — 기술 스파이크 (기획 확정보다 먼저, 1~2일)

설계안의 1-6·1-7 은 이 결과에 따라 바뀐다. **하나라도 막히면 범위를 다시 짠다.**

1. 3분 영상의 실제 **dataUri 크기와 웹뷰 메모리 거동** (iOS/Android, 저사양 포함)
2. 그 dataUri 서버 업로드 소요 시간 (모바일 회선)
3. 서버 ffmpeg 번인 시간·CPU — 현 OCI VM 2대 구성에서 감당되는지
4. **결과 영상을 폰 갤러리에 저장하는 SDK 경로**가 있는지
5. 구독 IAP 는 **샌드박스 미지원** → 실결제 테스트 계획
6. **`anonKey` 지속성 확인** — 앱 재설치 / 기기 변경 후에도 같은 값인가?
   공식상 계정 기준이라 유지될 것으로 보지만 명시 문구가 없어 **실환경에서 1회 확인**한다
   (샌드박스는 mock 반환이라 무의미). anon-key verify API 의 mTLS 요구 여부도 함께 확인.

**병행:** 콘솔 정산 정보 등록(영업일 2~3일) · mTLS 인증서 신청 — 리드타임이 개발보다 길다.

## 쟁점 1 — 구독 게이트를 앞에 둘 것인가

**문제.** 원안은 `목록 → 구독 → 사용`. 가치를 보여주기 전에 지갑을 요구한다. 자막 품질은 써봐야 안다.
앱인토스에서 빠르게 매출 낸 사례(디스팟 첫 달 1,000만원, 코심 첫 주 260만원, 돌돌디 월 2.1억)는
전부 **사기 전에 뭘 얻는지 아는** 유형이다.

**선택지.** ⓐ 원안 유지 ⓑ 첫 1편 완제품 무료 후 과금 ⓒ 대본까지만 무료

**결정 = ⓐ (사용자 확정).** 제안은 ⓑ 였으나 사용자가 원안을 재확인했다.
→ **따라오는 부담**: 설득을 S2(솔루션 상세)가 전부 져야 한다. Before/After 예시 영상이 필수가 된 이유다.
그리고 첫 결제 마찰이 높은 만큼 **가격 민감도가 올라간다**(쟁점 3).

## 쟁점 2 — 영상 범위를 무엇으로 제한할 것인가

**문제.** `getAlbumItems` 는 영상을 **dataUri** 로 준다. 100MB 영상 → base64 ≈ 133MB 를 웹뷰 메모리에
문자열로 올린다. iOS 미니앱 웹뷰에서 `getUserMedia({video})` 가 막힌
[사례](https://techchat-apps-in-toss.toss.im/t/ios-getusermedia-video-notallowederror/4540)도 있다.
검수 기준이 "2초 이내 · 비정상 메모리 증가 금지"라 **반려 사유가 될 수 있다.**
번인도 서버 ffmpeg 작업인데 현 OCI VM 2대 구성에 그 부하는 안 잡혀 있다.

**선택지.** ⓐ 무제한 ⓑ 60초 이하 세로 전용 ⓒ 스파이크 후 결정 ⓓ 길이 아닌 다른 기준

**방향 = ⓓ 용량·해상도 기준, 가로/세로 모두 (사용자 확정).**
**🔶 구체 수치는 전부 미확정** — 스파이크 1~3 결과로 정한다(1-6).

→ **남는 문제**: 용량은 사용자가 예측할 수 없다. 같은 30초라도 1080p/30fps 면 30MB,
60fps 면 75MB 다. 용량만으로 막으면 "왜 내 30초 영상은 안 되지?" 가 그대로 이탈이 된다.
그래서 **안내는 길이로, 방어는 용량으로** 2중 기준을 두기로 했다.

## 쟁점 3 — "자막만"으로 월 구독을 받을 수 있는가 🔶

**문제.** 경쟁 지형이 이미 무료다.

| | 가격 | 범위 |
|---|---|---|
| CapCut / Meta Edits | 무료 | 자막 + 편집 (플랫폼 사업자) |
| [Vrew](https://vrew.ai/ko/) (국산) | 무료 크레딧 200 / 라이트 9,900원 | 자막+더빙+번역+컷편집 |
| [Submagic](https://aisotools.com/pricing/submagic) | 무료 3편/월 / $20~ | 애니메이션 자막 |
| [Opus Clip](https://www.ngram.com/blog/opus-clip-vs-submagic) | $15~ | 롱폼 → 클립 추출 |
| [Captions](https://techcrunch.com/2026/03/24/mirage-raises-75m-to-continue-building-models-for-its-ai-video-editing-app-captions/) | 2025-01 freemium 전환 | TTM 인앱매출 $28.4M 인데도 무료 압박에 밀림 |

자막 단일 기능의 구독 가격은 전 세계적으로 무너지는 중이다. 게다가 **자막 니즈는 간헐적**이라
"매달 쓴다"는 구독의 전제가 약하다. 쟁점 1에서 체험을 뺐으니 가격 민감도는 더 올라간다.

**우리가 파는 것은 기능이 아니라 접근성이다** — 앱 설치·가입·PC 없이 토스 안에서 폰만으로.

**선택지.** ⓐ 월 구독만 ⓑ 구독 + 1편 단건 병행 ⓒ 단건/크레딧만
**제안 🔶 = ⓑ.** 간헐적 사용자를 단건이 받아낸다. 가격은 Vrew 9,900원보다 낮게(수수료 20% 감안).
금액은 스파이크로 원가 확정 후.

## 쟁점 4 — 토스 로그인을 붙일 것인가

**문제.** 원안은 "로그인 없이". 검수 항목에 **"기기 변경 시에도 기존 결제 데이터가 유지되어야 한다"**
가 있어, 익명키만으로 구독 소유권을 유지할 수 있는지가 쟁점이었다.

**확인 결과 — 익명키는 기기가 아니라 사용자(계정) 기준이다.**
토스 공식: *"미니앱마다 고유한 값이고, 같은 사용자는 같은 미니앱에서 항상 같은 값을 받아요."*
토스 로그인이 필요한 경우로 든 것은 *"본인 확인이나 중복가입 방지처럼, 앱인토스 밖 계정과
같은 사람인지 연결해야 할 때"* 뿐 — 기기 변경 복원은 로그인 사유가 아니다.
그리고 문서는 `getAnonymousKey()` → 서버 검증 → **파트너 서버가 `anonKey↔orderId` 매핑 관리**
흐름으로 로그인 없는 구독 운영을 안내한다.

**선택지.** ⓐ 익명키만 ⓑ 결제 시점에만 로그인 ⓒ 첫 진입부터 로그인

**결정 = ⓐ 토스 로그인 사용하지 않음 (2026-08-07, 사용자 확정).**
진입 마찰이 0이 되고, 플랫폼 문서상 결제 소유권 유지도 성립한다.

> 초기 검토에서 "기기 변경 복원은 userKey 만 보장한다"고 적었으나, 1차 출처를 대조한 결과
> 그 문구는 anonKey 를 배제하지 않는다. **리스크를 과대평가했던 것을 정정한다.**

→ **따라오는 부담 (3가지)**
1. **"기기 변경·재설치"를 명시한 공식 문구는 없다.** 커뮤니티
   [4279](https://techchat-apps-in-toss.toss.im/t/user-identifier/4279) 의 같은 질문에도 확답이 없다.
   거의 확실하지만 **결제 소유권이 걸린 만큼 실환경에서 한 번 확인한다** → 스파이크 6.
2. **구독 소유의 정본이 우리 DB의 `anonKey↔orderId` 매핑**이 된다. 유실되면 사용자는 돈을 내고
   못 쓴다. 백업·정합성 요구가 로그인 방식보다 높다. 또 **미니앱을 새로 출시하면 anonKey 가
   승계되지 않는다** — 앱 재출시 시나리오에서 구독이 끊긴다.
3. `CLAUDE.md` 의 "알림 구독·결제 등 → `appLogin()`" 규칙과 충돌 → **규칙 문서를 갱신해야 한다.**

## 쟁점 5 — 이름과 기능의 타깃이 다르다 🔶

**문제.** 앱 이름 "AI로 **마케팅** 영상 딸깍"(소상공인) / MVP "**기존 영상**에 자막"(이미 영상 가진 사람) /
로드맵 "유튜브 계정·쇼츠·방향성"(크리에이터) — 셋이 다른 사람을 가리킨다.
앱인토스 심사는 **과장·오인 표현을 반려 사유**로 본다.

**선택지.** ⓐ 이름 유지 + 문구로 정리 ⓑ 이름을 MVP에 맞게 조정 ⓒ MVP 를 이름에 맞게 확장
**제안 🔶 = ⓐ.** 이름은 로드맵 전체를 담는 그릇으로 두고, S2 에 "지금 제공: 기존 영상 자막"을 명시.
ⓒ 는 MVP 원칙에 반한다.

## 쟁점 6 — 작업 이력을 둘 것인가

**문제.** 초기 검토에서는 "3편째부터 필요"라며 제외했으나, 그 판단은 **단건 결제를 전제**로 한 것이었다.
쟁점 1에서 월 구독이 확정되면서 전제가 바뀌었다. 이력이 없으면 세 군데가 깨진다.

1. **이탈 복구 불가.** 입력이 최대 3분/50MB 라 업로드→STT→번인이 수십 초~수 분 걸린다.
   미니앱은 토스 안이라 알림·전화로 이탈이 쉬운데 **돌아올 자리가 없다.** 이게 진짜 필요 이유다 —
   아카이브가 아니라 **복구**.
2. **구독 재방문 근거 약화.** 월 정액은 "여러 편 만든다"가 전제인데 만든 게 남지 않는다.
   체험도 없어(쟁점 1) 첫 결제 마찰이 이미 높다.
3. **결과물 수령 실패의 안전망 부재.** 갤러리 저장 경로가 미확인(스파이크 4)이다.
   저장이 실패하면 다시 받을 방법이 없다.

**반대급부.** 영상 보관은 스토리지 원가 + 개인정보 리스크. "처리 후 즉시 삭제" 방침과 충돌한다.

**선택지.** ⓐ 제외 유지 ⓑ 작업 목록만(대본 보관·영상 단기) ⓒ 풀 보관함(폴더·검색·이름변경)

**방향 = ⓑ (사용자 확정). 🔶 구체 범위·보관 기간은 미확정.**
위 3개를 다 풀면서 원가·개인정보 리스크는 키우지 않는 방향이다. 대본(텍스트)은 보관 비용이
사실상 0이라 유지하고, **만료된 작업도 대본으로 번인만 다시 돌릴 수 있게** 하면 재사용 가치가 생긴다.
ⓒ 의 폴더·검색은 작업이 수십 개 쌓인 뒤의 문제 — MVP 범위 밖.

**미확정 🔶** — 영상 보관 기간(7일?) · 목록에 남길 작업 수 · 만료 후 재번인 허용 여부 ·
대본 보관 기간. 스토리지 원가가 나와야 정할 수 있다(스파이크 3).

# 4. 기각한 안

- **SRT 파일만 제공(번인 제외)** — 서버 인코딩 원가는 0이 되지만, **폰에서 SRT 로 할 수 있는 일이 없다.**
  SRT 는 PC 편집 워크플로의 산출물이다. "자막 입힌 영상을 준다"는 핵심 약속을 스스로 깬다.
- **텍스트→영상 생성을 MVP에 포함** — 로드맵 항목. 원가·품질 리스크가 자막의 몇 배다.
- **60초 세로 전용으로 축소** — 기술 리스크는 가장 낮지만 사용자가 대상 범위를 넓히기로 결정.
