# 빌드와 검증 파이프라인

#config-gradle #test-modularity

## Modulith 의존 (`backend/build.gradle.kts`)

```kotlin
val modulithVersion = "2.0.7"   // Boot 4.0.x ↔ Modulith 2.0.x

implementation(platform("org.springframework.modulith:spring-modulith-bom:$modulithVersion"))
implementation("org.springframework.modulith:spring-modulith-starter-core")
implementation("org.springframework.modulith:spring-modulith-starter-jpa")   // 이벤트 아웃박스
runtimeOnly("org.springframework.modulith:spring-modulith-actuator")         // /actuator/modulith

testImplementation("org.springframework.modulith:spring-modulith-starter-test")  // verify() + @ApplicationModuleTest
testImplementation("org.springframework.modulith:spring-modulith-docs")          // Documenter
```

> [!warning] Boot 버전과 라인을 맞춰야 한다
> Boot 4.0.x ↔ Modulith 2.0.x · Boot 4.1.x ↔ Modulith 2.1.x

| 아티팩트 | 없으면 |
|---|---|
| `starter-core` | `@ApplicationModule` 자체가 없다 |
| `starter-jpa` | 이벤트가 아웃박스에 안 남아 **유실**된다 |
| `starter-test` | `verify()` · `@ApplicationModuleTest` 불가 |
| `docs` | `Documenter` 불가 (다이어그램·캔버스) |
| `actuator` | `/actuator/modulith` 없음 |

## 커버리지

- 게이트: **LINE 95% / BRANCH 90%** (`jacocoTestCoverageVerification`, `check` 에 연결)
- **목표는 100%** — 95는 실패선이지 목표가 아니다. 새 기능의 변경 라인은 100%를 채운다.
- 제외: `*Application`, `config/**`, `dto/**`, `*Request`, `*Response`

> [!warning] 제외 목록을 늘려 게이트를 통과시키지 않는다
> 사유 없는 제외는 **커버리지 조작**이다. 미커버 라인이 남으면
> "왜 테스트할 수 없는가"를 먼저 묻는다 — 대부분은 테스트가 어려운 게 아니라 **설계가 새는 신호**다
> (정적 의존, 시간·랜덤 직접 사용, 과한 방어 코드).

## 스키마 — `ddl-auto: validate` 의 함정

운영은 `validate` 라 **스키마가 배포로 만들어지지 않는다.** 수동 DDL 이 **앱 배포보다 먼저** 적용돼야 한다.

| DDL | 왜 필요한가 |
|---|---|
| `deploy/sql/event-publication-v1.sql` | **아무 모듈도 이벤트를 안 써도 필요하다** — `starter-jpa` 가 아웃박스를 JPA 엔티티로 등록하므로 `validate` 가 검증한다 |
| `deploy/sql/auth-v1.sql` | `users` 테이블 |

> [!warning] 이 레포가 두 번 밟은 함정 — 둘 다 **로컬에서는 안 드러난다**
> | 실수 | 증상 |
> |---|---|
> | 테이블명을 **대문자**로 | 대소문자 구분하는 **리눅스 MySQL** 에서만 validate 실패 |
> | `CHAR(64)` 사용 | `wrong column type ... expecting varchar(64)` — JPA `String` 은 `VARCHAR` 를 기대한다 |
>
> → `AuthModuleBoundaryTest.수동_DDL_이_매핑과_일치한다` 가 엔티티 매핑을 읽어 SQL 파일과 대조한다.
> **배포 시점에야 터질 사고를 테스트로 당긴 것** — 수동 DDL 이 있는 모든 모듈이 복제해야 할 패턴이다.
