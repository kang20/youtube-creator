# 핸드오프 규격 — workspace 파일

> 세 에이전트는 **파일로만 통신한다.** 서로를 직접 호출하지 않고, 호출은 [implement 스킬](../SKILL.md)이 한다.
> 이 규격이 셋의 유일한 계약이므로, 각 에이전트 문서가 이 파일을 참조한다.

## 위치

```
backend/workspace/{name}/
└── v{n}/                             도메인 정의서 버전
    ├── requirements.md               요구 체크리스트 (버전·회차·라운드를 넘어 하나만 유지·갱신)
    ├── review{k}-round{r}-test.md    테스터 → 개발자 (무엇이 왜 실패했나 · 무엇을 고쳐야 하나)
    ├── review{k}-round{r}-dev.md     개발자 → 테스터 (무엇을 고쳤나)
    ├── review-{k}.md                 코드리뷰어 → 개발자·테스터 (PASS·RETRY 무관하게 남긴다)
    └── blockers.md                   도메인 정의서로 판정 불가 — 사용자 개입 필요 (버전 단위, 회차 없음)
```

**기호 정리 — 모든 문서 공통이다. 다른 뜻으로 쓰지 않는다.**

| 기호 | 뜻 | 범위 |
|---|---|---|
| `{n}` | 정의서 버전 (`{name}-v{n}.md` · `workspace/{name}/v{n}/`) | 1.. |
| `{k}` | 리뷰 회차 | 1..3 |
| `{r}` | 내부 라운드 | 1..5 |
| `{v}` | spec-verifier 검증 회차 | 1..3 |

`REQ-{n}` 의 `{n}`(요구 일련번호)과 판정 줄 `## 판정: RETRY ({n}건)` 의 `{n}`(🔴 항목 수)은
그 표기 안에서만 쓰는 지역 번호다. **경로와 파일명의 `{n}` 은 언제나 정의서 버전이다.**

- **workspace 는 정의서 버전으로 갈린다.** 경로 표기는 모든 문서에서
  `backend/workspace/{name}/v{n}/` 로 통일한다.
  정의서가 v2 로 오르면 `v2/` 를 새로 만들고 **k=1 · r=1 로 시작한다.** `v1/` 은 그대로 남긴다 —
  옛 버전의 판정 기록이 지워지면 무엇이 왜 바뀌었는지 대조할 근거가 사라진다.
- **`requirements.md` 는 직전 버전이 있으면 거기서 복사해 온 뒤 갱신하고, 첫 버전(v1)이면 새로 만든다.
  같은 버전 안에서는 재생성하지 않는다** — REQ-번호를 보존하기 위해서다.
- 첫 실행은 k=1 이다. RETRY 로 재개하면 k 가 1 오르고 r 은 1로 리셋된다.
  **단 `requirements.md` 와 REQ-번호는 회차를 넘어, 그리고 버전을 넘어 유지된다.**
- `backend/workspace/` 는 gitignore 대상이다. **커밋되지 않는다.**
- 라운드·회차마다 새 파일을 만든다(덮어쓰지 않는다). 같은 실패가 반복되는지 보이게 하기 위해서다.
  파일명에 `{k}` 와 `{r}` 이 둘 다 들어가야 회차가 바뀌어도 앞 파일이 덮이지 않는다.
- 예외는 `requirements.md` 하나다. **이것만 갱신한다** — 요구 목록은 라운드가 아니라 도메인의 것이기 때문이다.

## 공통 — 번호 표기

- 요구 번호는 **`REQ-{n}`** 이다. `R{n}` 을 쓰지 않는다 —
  [architecture.md](../../../../backend/docs/rule/architecture.md) 의 공개 표면 규칙 R1~R7 과 네임스페이스가 겹친다.
- 아키텍처 규칙을 인용할 때는 항상 **`architecture.md R1`** 처럼 문서명을 앞에 붙인다.
  문서명이 없으면 요구 번호인지 규칙 번호인지 읽는 쪽이 판정할 수 없다.

## requirements.md — 테스터가 쓴다 (직전 버전이 있으면 복사해 온 뒤 갱신 · v1 이면 새로 만든다)

도메인 정의서에는 U1·§5-2 같은 번호가 없다. **이 파일의 REQ-번호가 요구 추적의 유일한 수단이다.**

```markdown
# {name} 요구 체크리스트 (리뷰 {k}회차 / 라운드 {r} 기준)

| # | 요구(원문 그대로) | 출처 섹션 | 덮는 테스트 | 상태 |
|---|---|---|---|---|
| REQ-1 | 같은 주문은 몇 번 요청해도 정확히 한 번만 지급하고, 재요청도 성공으로 답한다 | payment-v1.md > 결제 도메인 | `GrantServiceTest#같은_주문을_두_번_지급해도...` | 덮임 |
| REQ-2 | 잔량은 절대 음수가 되지 않는다 | payment-v1.md > 횟수권 애그리거트 > 규칙 | — | 미덮임 |
| REQ-3 | 쿠폰·프로모션·무료체험은 범위 밖이다 | payment-v1.md > 결제 도메인(경계 선언) | — | N/A(범위 밖 선언 — 검증 대상 코드가 없다) |

- 전체 {n}건 — 덮임 {n} / 미덮임 {n} / N/A {n}
```

- **회차를 넘어, 그리고 버전을 넘어 하나만 유지한다.** 재개(k+1)해도 새로 만들지 않고 갱신하고,
  버전이 올라 `v{n+1}/` 로 옮겨가도 **직전 버전에서 복사해 온 뒤 갱신한다.**
  **첫 버전(v1)이면 새로 만든다** — 복사해 올 직전 버전이 없다.
  같은 버전 안에서는 재생성하지 않는다 —
  재생성하면 REQ-번호가 재배열돼 이미 박힌 테스트 주석이 다른 요구를 가리킨다
- 추출 대상은 둘이다: **요구 섹션의 불릿 전부** + **`## 도메인 모델` 의 `#### 규칙` 불릿 전부**.
  하위 불릿도 한 줄이면 한 항목이다 — "왜"를 붙인 하위 불릿에 검증할 규칙이 숨어 있는 경우가 많다
- **요구 섹션은 상태 헤더 다음의 첫 번째 `## ` 섹션이다. 제목 문자열로 찾지 않는다.**
  제목은 `## {도메인명} 도메인` 형식이고 `{도메인명}` 은 한글이어도 영문이어도 된다
  (선례 `## 결제 도메인` 이 정상이다) — 그래서 이름으로 grep 하면 깨진다
- **원문 그대로 옮긴다.** 요약하면 판정 기준이 조용히 바뀌어, 덮었다고 표시된 항목이 다른 것을 검증한다
- **상태는 셋뿐이다: `덮임` · `미덮임` · `N/A(사유)`.** 넷째 값을 만들지 않는다 —
  `보류`·`미검증` 같은 말이 끼면 집계가 무엇을 세는지 아무도 모른다
- 정의서가 모호해 blockers 로 올린 항목은 **`미덮임(blockers B{n})`** 으로 쓴다.
  덮이지 않은 것은 사실이고, 왜 덮지 못했는지는 괄호가 말한다
- **`N/A` 는 사유를 반드시 적는다.** 남발하면 커버리지 판정이 무의미해진다.
  사유 없는 `N/A` 는 미덮임으로 다룬다
- REQ-번호는 **한 도메인 안에서 재사용하지 않는다.** 요구가 사라져도 번호를 비워 두고,
  다음 항목에 그 번호를 다시 붙이지 않는다 — 테스트 주석이 다른 요구를 가리키게 된다
- 테스트 주석이 이 번호를 쓴다: `/** REQ-12 — 같은 주문을 두 번 지급해도 잔량은 한 번만 오른다 */`

### 정의서 버전이 올랐을 때 — 사라진 요구의 처리

새 버전 디렉토리 `v{n}/` 의 `requirements.md` 는 **직전 버전에서 복사해 온 뒤 갱신한다.**
그때 정의서에서 없어진 요구는 이렇게 다룬다.

- **행을 지우지 않는다.** 요구 원문에 빗금을 치고, 상태를 `N/A(v{n} 삭제 — 정의서에서 제거됨)` 로 둔다.

  | # | 요구(원문 그대로) | 출처 섹션 | 덮는 테스트 | 상태 |
  |---|---|---|---|---|
  | REQ-7 | ~~웹훅으로 구독을 새로 만들지 않는다~~ | payment-v1.md > 결제 도메인 | — | N/A(v2 삭제 — 정의서에서 제거됨) |

- **REQ-번호는 결번으로 남긴다(재사용 금지).** 이미 박힌 테스트 주석이 다른 요구를 가리키는 것을 막는다.
- 상태 어휘는 여전히 셋(`덮임`·`미덮임`·`N/A(사유)`)이다. **삭제분은 `N/A(사유)` 로 흡수된다** —
  넷째 값을 만들지 않는다.
- **삭제된 요구를 덮던 테스트는 tester 가 지운다.** 죽은 테스트가 커버리지를 왜곡한다.
  지웠다는 사실을 그 라운드의 `review{k}-round{r}-test.md` 에 적는다.

## review{k}-round{r}-test.md — 테스터가 쓴다 (매 라운드, 통과·실패 무관)

```markdown
# {name} 리뷰 {k}회차 / 라운드 {r} 테스트 보고

## 실행 결과
- 테스트: {통과}/{전체} · 실패 {n}건
- 변경 파일 라인 커버리지: {n}% (미달 파일: {목록})
- ModularityTest: 통과 | 실패({메시지})
- requirements.md: 전체 {n}건 — 덮임 {n} / 미덮임 {n} / N/A {n}

## 실패 상세   ← 통과 라운드면 이 절부터 아래를 통째로 생략한다

### 1. {테스트 클래스}#{메서드}
- **덮으려던 것**: REQ-12 — payment-v1.md > 주문 애그리거트 > 규칙   ← 근거를 반드시 REQ-번호로
- **기대**: {무엇이 일어나야 하나}
- **실제**: {무엇이 일어났나 — 예외 메시지·응답 코드 원문}
- **원인 분류**: 구현 누락 | 구현 오류 | 설계 모호 | 테스트 오류
- **수정 지시**: {파일:줄 단위로 무엇을 어떻게. "구현 필요" 같은 말 금지}

### 2. ...

## 커버리지 미달
| 파일 | 미달 라인 | 어떤 분기가 안 덮였나 | 필요한 것 |
|---|---|---|---|
- **테스트를 더 쓰면 되는 것**과 **죽은 코드라 지워야 하는 것**을 구분해서 적는다.

## 개발자가 손대면 안 되는 것
- `src/test/**` — 테스트는 테스터가 관리한다. 통과시키려고 테스트를 고치지 마라.
- {그 외 이번 라운드 범위 밖 파일}
```

- **통과·실패 무관하게 매 라운드 쓴다.** 통과면 `## 실행 결과` 만 채우고
  `## 실패 상세` 이하는 생략한다 — 통과 라운드의 테스트 수·커버리지·requirements 집계가 남지 않으면
  implement 결과 보고와 `/docs-sync` 리포트가 근거를 잃는다

**원인 분류가 이 문서의 핵심이다.**

| 분류 | 뜻 | 다음 행동 |
|---|---|---|
| 구현 누락 | 도메인 정의서에 있는데 코드가 없다 | 개발자가 구현 |
| 구현 오류 | 코드가 있는데 정의서와 다르게 동작 | 개발자가 수정 |
| 설계 모호 | 정의서만으로 무엇이 맞는지 판정 불가 | **blockers.md 로 올린다** — 개발자가 추측하면 안 된다 |
| 테스트 오류 | 테스트가 정의서를 잘못 읽었다 | **테스터가 자기 테스트를 고친다.** 개발자에게 넘기지 않는다 |

## review{k}-round{r}-dev.md — 개발자가 쓴다

```markdown
# {name} 리뷰 {k}회차 / 라운드 {r} 개발 보고

## 처리한 지시
| 지시 | 처리 | 파일 |
|---|---|---|
| 1. {테스트 보고 또는 리뷰의 지시} | 구현 / 수정 / **미처리** | {경로} |

## 미처리 항목 (있으면)
- {지시} — {왜 못 했나}. 정의서로 판정 불가하면 blockers.md 에도 올렸는지 명시.

## 도메인 정의서 대비 구현 상태
- `## 도메인 모델` 의 구성요소 중 구현 완료: {목록}
- 아직 없는 것: {목록}
- 용어 사전에 없는 이름을 쓴 곳: {없으면 "없음"}

## 컴파일 확인
- `./gradlew compileJava` 통과 여부
```

## review-{k}.md — 코드리뷰어의 판정을 스킬이 남긴다 (PASS·RETRY 무관)

**양식의 정본은 [code-reviewer](../../../agents/code-reviewer.md) 의 출력 형식이다.**
그 출력이 그대로 이 파일이 되므로(저장만 스킬이 한다), 이 문서가 그 출력에 맞춘다. 반대가 아니다.

**PASS 여도 남긴다.** pm 이 5단계 완료를 탐지할 근거가 되고,
마지막 RETRY 파일만 보고 "아직 미완"으로 오판하는 것을 막는다.

RETRY 를 트리거하는 것은 **세 항목(🔴)뿐**이다.
그 밖의 지적(🟡)은 루프에 넣지 않고 사용자 판단으로 남긴다.

```markdown
## 코드 리뷰: {name} ({k}회차)

검토 범위: {파일 수}개 파일 ({신규 n} / {수정 n})

### 🔴 요구 누락
**1. {한 줄 요약}** → developer
- 근거: {정의서 원문 인용}
- 문제: {코드가 무엇을 하고 있나 · 어디인가}
- 수정: {무엇을 어떻게}

### 🔴 코드 오염
(같은 형식, 항목마다 → developer 또는 → tester)

### 🔴 테스트 누락
(같은 형식, 항목마다 → tester)

### 🟡 검토 권장 (RETRY 트리거 아님)
### 🔵 정의서 역반영 필요
### ✅ 잘 된 것

## 판정: PASS
```

- **첫 줄은 `## 코드 리뷰: {name} ({k}회차)` 다.** H1 을 쓰지 않는다.
- **마지막 줄은 반드시 `## 판정: PASS` 또는 `## 판정: RETRY ({n}건)` 이다.** pm 이 이 줄을 grep 한다.
  **이 줄에 한해 `{n}` 은 정의서 버전이 아니라 🔴 항목 수다** — 🟡·🔵 는 세지 않는다.
- **PASS 여도 파일을 남긴다.** 🔴 절은 비우거나 생략하고, 🟡·🔵·✅ 는 그대로 남긴다.
- **🔴 항목마다 `→ developer` / `→ tester` 를 표시한다.** 누구 몫인지 없으면 개발자가 테스트까지 손대
  영역 분리가 무너진다
- **implement 는 이 표시만 보고 배분한다.** 카테고리로 추정하지 않는다 —
  '요구 누락' 안에도 담당이 tester 인 항목(requirements.md 추출 누락)이 있다
- 요구 누락은 **정의서 원문을 인용**한다. 인용이 없으면 리뷰어의 해석과 구별되지 않는다
- 코드 오염 유형의 정본은 [code-reviewer](../../../agents/code-reviewer.md) 문서다. 여기서 늘리지 않는다

## blockers.md — 누구든 쓴다 (사용자 개입 필요)

```markdown
# {name} 블로커

## B1. {한 줄 요약}
- **발견**: 리뷰 {k}회차 / 라운드 {r}, {누가}
- **상황**: 도메인 정의서의 {섹션}이 무엇을 말하는지, 왜 그것만으로 부족한지
- **선택지**: A) ... B) ... (각각의 결과)
- **추천**: {있으면, 근거와 함께}
- **막힌 것**: {이것 때문에 무엇을 못 하는지}
```

- 블로커가 생기면 **루프를 멈춘다.** 추측으로 진행하면 잘못된 구현 위에 테스트가 쌓인다.
- 해소는 `/develop-design {name}` 으로 **도메인 모델을 보강**하는 것이 정석이다.
  모델로 답할 수 없고 요구 자체가 정해지지 않았다면 `/usecase {name}` 까지 거슬러 올라간다.
- 정의서가 바뀌면 버전이 오른다. 되돌아온 뒤에는 **새 정의서 파일(`{name}-v{n+1}.md`)과
  새 workspace 디렉토리(`backend/workspace/{name}/v{n+1}/`)로 다시 시작한다** — k=1 · r=1 부터다.
- **버전 안에서 하나만 유지한다.** 다음 실행 0단계에서 항목별로 해소 여부를 확인하고,
  해소분은 같은 `v{n}/` 안의 `blockers-resolved-{날짜}.md` 로 옮긴다 —
  남겨 두면 옛 블로커가 새 실행을 계속 멈춘다.
- **직전 버전 디렉토리 `backend/workspace/{name}/v{n-1}/blockers.md` 가 있으면
  그 항목이 이번 정의서로 해소됐는지 함께 확인하고, 미해소분은 `v{n}/blockers.md` 로 옮겨 적는다.**
  버전이 갈리면 옛 블로커가 시야 밖으로 나가, 일부만 해소됐을 때 나머지가 조용히 사라진다.

## 규격을 지키는 이유

- **REQ-번호 강제** — 도메인 정의서에는 번호가 없다. 근거를 REQ-번호로 적지 않으면
  실패했을 때 "이 테스트가 맞나"부터 다시 따져야 한다.
- **원문 그대로 옮기기** — 요약본으로 판정하면 요약한 사람의 해석이 사양이 된다.
- **원인 분류 강제** — 분류가 없으면 개발자가 테스트 버그까지 떠안고 코드를 고친다.
- **지시 수신자 표시** — 리뷰 지적이 뒤섞이면 한 에이전트가 남의 영역을 건드린다.
- **라운드·회차별 파일** — 같은 실패가 2라운드 연속이면 접근이 틀린 것이다. 파일이 남아야 그게 보인다.
  파일명이 `{k}` 와 `{r}` 을 둘 다 담아야 회차가 바뀌어도 앞 회차 기록이 살아남는다.
