# 완성 예시 — 섹션 하나 전문

실제 프로젝트(유튜브 자막 SaaS)에서 나온 섹션을 그대로 옮긴 것이다. 밀도와 문장 톤의 기준으로 삼는다.

주목할 점:

- **기각 카드가 채택 카드보다 먼저** 온다. 검토했던 순서대로 읽히게 하는 배치다.
- 기각 카드에도 **장점(`p`)이 세 줄** 있다. 나쁜 안이라서 버린 게 아니라, 좋은 점이 있었는데도 특정 이유로 버렸다는 게 드러나야 한다.
- 채택 카드에 **단점이 있다.** 대가 없는 선택은 없다.
- 칩 라벨에 `기각 (초기 결론)` / `채택 (수정된 결론)`을 붙여 **번복 사실**을 카드 단계에서 노출한다.
- `cue-arrow`가 `DB 라인 저장 --> 오브젝트 스토리지 파일 저장`으로 이동 경로를 한눈에 보여준다.
- 미해결 항목으로 이어지는 지점에 `→ Q07` 참조를 남긴다.

## 문장 톤 대조

| 쓰지 않는다 | 쓴다 |
|---|---|
| 비효율적이므로 적합하지 않다 | 재인코딩이 필요해 원가가 수십 배로 뛴다 |
| 여러 가지를 고려하여 결정했다 | 접근 패턴이 통째 읽기뿐이라 관계형의 이점을 쓰지 않는다 |
| 확장성을 고려하면 좋을 것 같습니다 | 지금 규모에서는 쓸 일이 없다. 필요해지면 그때 바꾼다 |
| Redis Stream을 사용하기로 하였습니다 | 큐는 Redis Stream으로 간다 |

근거를 적을 때는 **검증 가능한 사실**까지 내려간다. 형용사에서 멈추면 6개월 뒤의 자신이 그 판단을 재현할 수 없다.

## 번복을 기록하는 방식

이 섹션이 좋은 예다. 번복은 세 군데에 동시에 드러난다.

1. `lede` — "처음 낸 결론이 뒤집힌 주제"
2. 칩 라벨 — `기각 (초기 결론)` / `채택 (수정된 결론)`
3. `cue-arrow` — `DB 라인 저장 --> 오브젝트 스토리지 파일 저장`

번복을 숨기면 문서는 매끈해지지만 가장 값진 정보가 사라진다. **무엇을 놓쳤다가 어떻게 발견했는지**가 6개월 뒤 가장 쓸모 있는 기록이다.
