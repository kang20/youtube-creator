# domain-model — 도메인 모델 시각화

**기본 산출물은 `backend/docs/model/master.md` 하나다.** 그림만 그린다.

```
backend/docs/model/
├── master.md              전 모듈 통합 다이어그램 — Mermaid 코드블록만   ← 기본 산출물
│
│   ↓ 아래는 사용자가 명시적으로 요청할 때만 만든다
├── {module}-notes.md      책임·불변식·경계 규칙·주의사항·미확정
├── {module}-state.md      상태 전이
└── {module}-flow.md       모듈 간 상호작용 흐름
```

`master.md` 는 **열면 그림만 보인다.** 설명·표·제목을 넣지 않는다.

**부연 문서는 기본 산출물이 아니다.** 그릴 때 알게 된 것(불변식·이탈·미확정)은
**5단계에서 말로 보고**하고, 사용자가 "노트로 남겨줘"라고 할 때만 파일로 만든다.
묻지 않고 먼저 만들지 않는다.

Modulith `Documenter` 는 "모듈이 서로 어떻게 얽히는가"까지만 자동으로 그린다.
**모듈 안이 어떻게 생겼는가는 자동 추출이 불가능하다** — 이 스킬이 그 자리를 메운다.

**이 스킬은 코드를 작성하지 않는다.** 문서만 만든다.

## 왜 자동화가 아니라 수기인가

| 그리려는 것 | 자동 추출 | 이유 |
|---|---|---|
| 모듈 간 의존 | ✅ Modulith `Documenter` | 패키지 의존에서 기계적으로 나온다 |
| 애그리거트 루트 목록 | ⚠️ 탐지는 되나 문서화 불가 | 엔티티가 `internal` 이라 캔버스의 *exposed* 필터에 걸린다 |
| **애그리거트 경계** | ❌ | "어디까지가 한 트랜잭션 단위인가"는 설계 의도다 |
| **엔티티 책임·불변식** | ❌ | 코드에 없다. 사람 머릿속에 있다 |
| **엔티티 간 논리 참조** | ❌ | 물리 FK 를 쓰지 않으므로 스키마에 관계가 없다 |

→ **코드에서 뽑을 수 있는 건 뽑고, 설계 의도는 사용자에게 묻는다.** 추측해서 채우지 않는다.

## 입력

- `{module}` — Modulith 모듈명 (`auth` · `payment` · `shared` · `config` · `bootstrap`)
  - 사용자가 한글 표시명(`인증` · `결제·이용권`)으로 부를 수 있다 → `package-info.java` 의
    `displayName` 으로 대조해 패키지명을 찾는다
  - 모듈명이 모호하거나 없는 모듈이면 **묻는다**. 임의로 고르지 않는다
- **부연 문서 요청** (선택) — "상태 전이도 그려줘" · "노트도 남겨줘" · "흐름도 만들어줘"
  같은 **명시적 지시가 있을 때만** 해당 파일을 만든다

## 참조 (필요할 때 읽는다)

| 무엇이 필요할 때 | 어디를 |
|---|---|
| 파일별 양식·Mermaid 작성 규약 | [references/template.md](references/template.md) |
| 모듈 경계·의존·이벤트 규칙 | [architecture.md](../../../backend/docs/rule/architecture.md) |
| 이 모듈의 요구·정책 | `backend/docs/domain/{module}.md` |
| 이 모듈의 설계 결정 | `backend/docs/domain/{module}-design.md` |
| 왜 그렇게 정했나 | `backend/docs/adr/` |
| 정본 — 실제 코드 | `backend/src/main/java/kang20/ytcreator/{module}/` |

> **정본은 코드다.** 설계서와 코드가 다르면 **코드를 그리고**, 그 불일치를 5단계에서 보고한다.
> 문서를 믿고 코드에 없는 것을 그리지 않는다.

## 절차

### 0. 사전 검증
- backend 브랜치인지 확인
- `master.md` 는 **항상 부분 갱신**이다 — 이 모듈 구역만 고치고 다른 모듈 구역은 손대지 않는다
  - 주석의 구역별 `근거 커밋` 과 현재 HEAD 를 비교해 **그 사이 변경된 파일부터** 본다
- 부연 문서가 **이미 있고** 이번에 요청받았으면 → 덮어쓰지 않고 갱신 모드로 사용자 확인
- **모듈 종류를 먼저 가른다** — 그리는 방법이 통째로 달라진다

  | 종류 | 판정 | 그리는 것 |
  |---|---|---|
  | **도메인 모듈** | `@Entity` 가 하나 이상 있다 | 애그리거트 지도 + ERD |
  | **집계 컨텍스트** | `@Entity` · 리포지토리가 **0개**이고 다른 모듈의 결과를 합치기만 한다 (`bootstrap`) | **집계 DTO 구성도** (아래 3단계) |
  | **그릴 것 없음** | 엔티티도 없고 집계도 아니다 (`config` 같은 설정·조립 전용) | 없음 — 사실을 보고하고 중단 |

  집계 컨텍스트는 "엔티티가 없어서 못 그리는 모듈"이 아니다. **저장소를 갖지 않는 것이 그 모듈의
  정체성**이므로, 그 사실이 드러나게 그린다

### 1. 코드에서 사실 수집 (추측 금지)

이 순서로 **전부** 읽는다. 요약본이 아니라 실제 파일을 연다.
`master.md` 만 만들 때도 전부 읽는다 — **경계 판정의 근거가 여기서 나오기 때문이다.**

1. `{module}/package-info.java` — 표시명 · `allowedDependencies` · 모듈 타입
2. `{module}/internal/entity/**` — 필드 · 타입 · 제약(`nullable` · `unique` · `length`) · enum · 생성자 · 상태 판정 메서드
3. `{module}/internal/**/repository/**` — 어떤 엔티티에 리포지토리가 있는가
   (**리포지토리가 있는 엔티티 = 애그리거트 루트 후보**. 확정은 2단계에서 사용자와)
4. `{module}/*Port.java` 등 모듈이 **밖에 노출한 타입** — 다른 모듈이 이 모듈을 어떻게 쓰는가
5. `{module}/internal/service/**` — 트랜잭션 경계 · 한 메서드가 함께 저장하는 엔티티들
   (**같은 트랜잭션에서 함께 바뀌는 엔티티 = 같은 애그리거트 후보**)
6. 이벤트 발행/구독 — `@EventListener` · `ApplicationEventPublisher`
7. 이 모듈을 참조하는 **다른 모듈** — `allowedDependencies` 에 이 모듈이 있는 쪽

### 2. 애그리거트 경계 판정 — **사용자에게 확인받는다**

수집한 사실로 **경계 초안**을 만들되, 근거를 함께 제시하고 확인받는다.

```
초안: payment 모듈 = 애그리거트 3개
  ① PaymentOrder (단독)         근거: 전용 리포지토리 · 다른 엔티티와 함께 저장되지 않음
  ② Subscription ← UsageTicket  근거: {메서드}가 한 트랜잭션에서 함께 씀
  ③ CreditBalance (단독)        근거: 전용 리포지토리 · 낙관적 락 필드 보유
이대로 맞나?
```

- 근거가 갈리면(리포지토리는 따로인데 같이 저장된다 등) **양쪽 해석을 보여주고 묻는다**
- 사용자가 정정하면 그대로 따른다 — 코드보다 설계 의도가 우선인 유일한 항목이다
- **확정된 경계와 코드 실제 접근 경로가 다르면** 그림은 확정안대로 그리고,
  이탈 사실은 5단계에서 보고한다
- 끝내 확정되지 않으면 **그 부분을 그리지 않고** 5단계에서 🔶 로 보고한다.
  **임의 확정 금지** (CLAUDE.md 규칙)

### 3. `master.md` 작성

[references/template.md](references/template.md) 의 양식과 Mermaid 규약을 따른다.

### ⚠️ 그림은 **하나**, 종류는 **`classDiagram`**

`master.md` 에는 **`classDiagram` 블록 딱 하나**만 둔다. ERD 를 따로 두거나 flowchart 를
덧붙이지 않는다. **전 모듈이 한 그림 안에 있어야 경계가 보인다** — 쪼개는 순간 그 값이 사라진다.

**`flowchart` 를 쓰지 않는 이유**: 노드 라벨에 `<br/>` 로 필드를 나열하면 **줄글이 되어 읽히지
않는다.** `classDiagram` 은 어트리뷰트가 클래스 박스 안에 **한 줄씩 표처럼 쌓인다** — 어느
엔티티에 어떤 필드가 있는지 눈으로 스캔된다. 도메인 모델 그림은 이 형태여야 한다.

공통 규칙:
- Mermaid 코드블록과 HTML 주석 외에 **아무것도 쓰지 않는다**
- 주석의 이 모듈 구역 `근거 커밋`·`갱신일` 을 갱신한다
- 다른 모듈 구역은 손대지 않는다

#### 구조

```
classDiagram
    direction LR

    namespace auth {            ← Modulith 모듈 하나 = namespace 하나 (ASCII 모듈명)
        class User {
            <<애그리거트 루트>>   ← 역할은 스테레오타입이 밝힌다
            +UserId id  PK       ← 어트리뷰트 한 줄 = 표 한 행
            ...
        }
    }
```

- **모듈**을 `namespace` 로 묶는다. 이름은 **ASCII 모듈명**(`auth`·`payment`·`bootstrap`) —
  한글 표시명은 HTML 주석의 매핑에 적는다 (`namespace` 이름에 공백·괄호를 넣으면 파싱이 깨진다)
- **역할은 `<<스테레오타입>>`** 으로 — `<<애그리거트 루트>>` · `<<구성 엔티티>>` · `<<집계 DTO>>`
- **어트리뷰트**는 `+타입 이름  제약` 한 줄씩. 식별자·상태·불변식에 관여하는 것만
- 상태 판정 메서드가 불변식을 드러내면 함께 적는다 (`+isRevoked() boolean`)
- 애그리거트 내부·중첩 DTO 는 **`*--`**, 경계를 넘으면 **`..>`**
- 라벨에 안 들어가는 **불변식은 `note for`** 로 붙인다

#### 집계 컨텍스트도 같은 그림 안에

**별도 다이어그램을 만들지 않는다.** 같은 `classDiagram` 에 `namespace` 하나로 들어간다.

- 스테레오타입에 **`<<집계 DTO · 자기 저장소 없음>>`**
- DTO 는 **필드를 전부** 적는다 — 도메인 엔티티는 핵심 필드만 적는 것과 반대다.
  DTO 는 프론트 계약이라 전부가 의미다
- 중첩 DTO 는 `*--` 로 잇는다
- **DTO 에서 출처 엔티티로 `..>`** 를 긋고, 라벨에 **필드가 어디서 왔는지** 적는다 —
  이게 집계 구역의 핵심 정보다 (예: `registeredAt ← createdAt`)
- 계약상 **일부러 빼는 필드**는 `note for` 로 남긴다 (예: 내부 식별자 미노출)

> **"집계"라는 말을 라벨에서 빼지 마라.** 저장소를 갖지 않는다는 사실이 이 모듈의 정체성이고,
> 여기에 엔티티가 생기면 그건 집계가 아니라 새 도메인이다. 라벨이 그 경계를 지킨다.

**여기서 끝이다.** 부연 문서는 요청받지 않았으면 만들지 않는다.

### 4. 부연 문서 — **명시적 요청이 있을 때만**

사용자가 요청한 것만 만든다. 요청하지 않은 파일을 "겸사겸사" 만들지 않는다.

| 요청 | 파일 | 조건 |
|---|---|---|
| "노트" · "책임" · "설명 남겨줘" | `{module}-notes.md` | — |
| "상태 전이" · "상태도" | `{module}-state.md` | 상태 필드가 있을 때만. 없으면 그 사실을 알리고 만들지 않는다 |
| "흐름" · "상호작용" · "시퀀스" | `{module}-flow.md` | 다른 모듈과 얽힐 때만 |

**내용이 없으면 요청받았더라도 만들지 않는다.** 빈 껍데기 문서는 만들지 않고 이유를 보고한다.

### 5. 렌더링 검증

작성 후 **Mermaid 문법을 점검한다.** 깨진 다이어그램은 없는 것만 못하다.

- 코드펜스가 ` ```mermaid ` 로 열렸는가
- `flowchart` 노드 라벨에 한글·`·`·`(` 가 들면 **따옴표로 감쌌는가** (`A["결제·이용권"]`)
- `erDiagram` 의 엔티티명에 하이픈·점이 없는가 (Mermaid 가 파싱 못 한다)
- 관계 카디널리티 기호가 짝이 맞는가 (`||--o{` · `||..o{`)
- **`master.md` 에 Mermaid 코드블록과 HTML 주석 외의 것이 없는가**

문법이 의심스러우면 **다이어그램을 단순화한다**. 화려함보다 렌더링이 우선이다.
실제 렌더링을 돌리지 않았다면 **"문법 점검만 했다"고 사실대로 보고한다.**

### 6. 보고 + 커밋

**그림에 담기지 않은 것을 여기서 말로 전달한다.** 이 보고가 부연 문서를 대신한다.

- 애그리거트 경계 판정과 그 근거
- **확정안과 코드의 이탈** — 있으면 반드시. 고칠 것인지 예외인지 판단까지
- **코드 ↔ 설계서 불일치** — 이 스킬의 부산물 중 가장 값어치 있다
- 발견한 불변식·주의사항 중 기록해둘 만한 것
- 🔶 미확정으로 남은 것

그 다음 **부연 문서로 남길지 제안한다** — 제안만 하고 만들지 않는다.

```
위 내용 중 남겨둘 만한 게 있으면 말해달라:
  auth-notes.md   책임·불변식·이탈 기록
  auth-state.md   RefreshToken 상태 전이
  auth-flow.md    bootstrap·config·payment 와의 상호작용
```

커밋: `docs({module}): 도메인 모델 시각화` / 갱신 시 `docs({module}): 도메인 모델 갱신 — {무엇}`

## 성공 조건

### `master.md` (항상)
- [ ] **Mermaid 코드블록과 HTML 주석(`<!-- -->`) 외에 아무것도 없다** — 제목·산문·표·링크 전부 금지
- [ ] **`classDiagram` 블록이 딱 하나다** — ERD·flowchart 를 따로 두지 않았다
- [ ] 모든 모듈이 **같은 그림 안**에 `namespace` 로 있다 (이름은 ASCII 모듈명)
- [ ] 다른 모듈 구역을 건드리지 않았다
- [ ] 주석의 이 모듈 구역에 **근거 커밋·갱신일**이 갱신됐다

### 도메인 모듈일 때
- [ ] 이 모듈의 **모든 엔티티**가 `class` 로 있다
- [ ] 어트리뷰트가 **한 줄씩** 적혔다 (`<br/>` 로 이어붙인 줄글이 아니다)
- [ ] **식별자·상태·불변식 필드**만 있다 (전 컬럼 나열은 하지 않았다)
- [ ] **`<<애그리거트 루트>>`** 스테레오타입으로 루트가 표시됐다
- [ ] 애그리거트 내부는 **`*--`**, 경계를 넘으면 **`..>`** 로 구분됐다
- [ ] 경계를 넘는 참조가 **ID 값 참조**로 그려졌다 (객체 참조로 그리지 않았다)
- [ ] 애그리거트 경계가 **사용자 확인을 거쳤다** (추측으로 확정하지 않았다)

### 집계 컨텍스트일 때
- [ ] **같은 classDiagram 안**에 `namespace` 로 들어갔다 (별도 다이어그램을 만들지 않았다)
- [ ] 스테레오타입에 **`<<집계 DTO · 자기 저장소 없음>>`** 이 있다
- [ ] 응답 DTO 의 **필드가 전부** 있다
- [ ] **필드가 어디서 왔는지**가 `..>` 라벨에 있다 (예: `registeredAt ← createdAt`)
- [ ] 계약상 일부러 뺀 필드가 `note for` 로 남았다

### 부연 문서 (요청받았을 때만)
- [ ] **요청받은 파일만 만들었다** — 겸사겸사 만든 파일이 없다
- [ ] `-notes.md` 를 만들었다면 엔티티마다 **책임 한 줄 + 불변식**이 있다 (필드 나열만 하지 않았다)
- [ ] `-state.md` 를 만들었다면 실제로 상태 필드가 있는 엔티티다
- [ ] 헤더에 **근거 커밋 해시**와 갱신일, `master.md` 로 돌아가는 링크가 있다

### 공통
- [ ] Mermaid 문법 오류가 없다
- [ ] 그림에 안 담긴 발견(이탈·불일치·미확정)이 **보고로 전달**됐다
- [ ] 요구·API JSON·커버리지 수치를 **복사하지 않고 링크**했다
- [ ] 코드가 작성되지 않았다
- [ ] 커밋됨

## 안전장치

- **기본은 `master.md` 하나** — 부연 문서는 명시적 요청 없이 만들지 않는다. 제안까지만
- **그림도 하나** — `classDiagram` 블록을 늘리지 않는다. 종류가 다르다고 다이어그램을 쪼개지 않는다
- **어트리뷰트를 줄글로 만들지 않는다** — `flowchart` 노드에 `<br/>` 로 필드를 이어붙이면
  읽히지 않는다. 클래스 박스의 한 줄 = 표 한 행이다
- **"집계" 라벨을 빼지 않는다** — 저장소 없음이 그 모듈의 정체성이다. 엔티티가 생기면 새 도메인이다
- **`master.md` 는 Mermaid 전용** — 설명을 넣고 싶어지면 그건 보고로 말할 것이다. 예외 없다
- **`master.md` 는 부분 갱신** — 호출된 모듈 구역만 고친다. 다른 모듈 그림을 건드리지 않는다
- **발견을 삼키지 않는다** — 파일로 안 남기더라도 이탈·불일치·미확정은 **반드시 보고**한다
- **코드가 정본** — 설계서에만 있고 코드에 없는 것은 그리지 않는다
- **추측 금지** — 애그리거트 경계·불변식은 사용자에게 묻는다. 🔶 를 임의 확정하지 않는다
- **덮어쓰기 금지** — 기존 부연 문서가 있으면 갱신 모드로 확인
- **빈 파일 금지** — 내용이 없으면 요청받았더라도 만들지 않고 이유를 보고한다
- **문서만** — 코드·테스트·빌드 설정을 건드리지 않는다
- **Mermaid 만** — PlantUML 을 쓰지 않는다. GitHub 이 렌더링하지 못한다
- **MVP 범위 우선** — 백로그·미구현 기능은 그리지 않는다

## 갱신 주기

자동 검사를 걸지 않는다 — **수기 문서라 드리프트를 기계가 못 잰다.**
대신 아래 시점에 사용자가 이 스킬을 다시 부른다.

```
엔티티 필드 추가/삭제 · 새 엔티티 · 애그리거트 경계 변경
   → /domain-model {module}   (master.md 의 해당 구역만 갱신)
```

`/implement` 로 도메인을 구현한 직후, `/docs-sync` 마감 전이 가장 자연스러운 자리다.

## 파이프라인 위치

```
/usecase {name}          요구      docs/domain/{name}.md
/develop-design {name}   설계      docs/domain/{name}-design.md
/implement {name}        구현      src/main · src/test
   ▼
/domain-model {module}   모델 그림  docs/model/master.md   [이 스킬]
   ▼
/docs-sync               마감
```
